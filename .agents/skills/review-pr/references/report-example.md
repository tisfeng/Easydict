# 复杂复审报告示例

仅在需要编写复杂 PR 复审报告时阅读。替换所有占位内容；[报告契约](reporting.md)、实际
快照和证据优先于本示例。简单 PR 缩短内容并省略空的可选模块，仍保留内容介绍和模块间分割线。
本示例包含可选的冲突集成结果及本地提交回执；未发生这些操作时省略对应内容。报告主体和
附录按 [组合规则](reporting.md#与冲突处理和提交回执组合) 排列，交付前核对实际生成内容。

```markdown
## 审查结论：建议修复后再合并

<一句话给出审查建议及主要阻塞项；有影响结论的验证缺口时说明>。

功能目标：<满足程度及证据边界，不重复下方的功能介绍>。

实现方式：<当前路径是否足以达成目标、比较依据与取舍；有更优替代时说明影响范围，没有时写明当前方式已足够>。

代码正确性：<缺陷/回归判断，与功能验证不足分别说明>。

本轮复审：已修复 <count> · 仍存在 <count> · 新增 <count>；另有 <count> 项决策待确认。

线程状态：最终开放 <count> 条；说明已修复但仍开放、只读未操作或无法确认的实际情况。

CI 与本地验证：仅列出实际结果和限制。

**行动项**

- F1：<短标题和建议动作>。
- Q1：<需要用户确认的范围或行为决策>。

---

## PR 内容介绍

<用短段落说明原问题、为什么需要这个 PR，以及合并后用户或开发者可感知的变化；必要时链接关联 issue>。

主要变化：

- <变化一及其作用>。
- <变化二及其作用>。

使用方式：<功能入口、典型操作及前提；内部变更按需要说明调用或维护方式，不适用时省略>。

实现思路：<串起核心流程及关键模块，为下方问题提供上下文；简单改动可省略>。

范围与限制：<有实质影响的依赖、未覆盖场景或待验证体验；区分描述承诺、代码实现与实际验证，不适用时省略>。

---

**触发与影响：** <可复现条件和用户/系统影响>。

**证据：** <当前代码、diff 或调用链证据>。

**建议修复：** <最小具体修改>。

**建议验证：** <针对性检查>。

---

**触发与影响：** <可复现条件和影响>。

- 范围：<实际审查边界及未覆盖内容，不重复上方 PR 内容介绍>。
- 目标核对：<关键验收条件及来源、实现/测试证据、实际判断；已读正文与讨论覆盖限制>。
- 方案评估：<当前实现方式、替代方案与代价、推荐动作或“当前已足够”的可核对结论>。
- 远程 Head：<完整 SHA>。

- 本地集成提交：`<完整 SHA>`；<parent/ancestry 核验结果、冲突文件及解决原则>。
- 远程状态：<是否 push、最终刷新观察到的状态>；本地解决与远程状态分别报告。

**已执行验证与限制**

- 已执行：<实际检查及结果>。
- CI：<通过、失败或 pending>。
- 未运行／受阻：<限制及其对结论的影响>。

**刷新与操作**

- 最终刷新：<head 是否一致、PR updatedAt、线程和回复覆盖情况>。
- 需求刷新：<标题/描述、issue 关联/正文和已采用讨论是否变化，受影响目标的复核结果>。
- 线程计数：初始开放 <count> · 本轮确认 resolve <count> · 最终开放 <count>。
- 实际操作：<本地和远程操作，或明确只读>。
```
