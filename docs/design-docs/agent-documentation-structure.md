# Agent 文档结构设计

- 状态：adopted
- 初次记录：2026-08-26

## 背景

Agent 需要快速找到当前任务的约束，人类需要理解这些约束为何存在，仓库还需要保留
执行过程、完成结果和外部来源。如果入口、规则、设计理由和参考资料混在同一文件中，
入口会持续膨胀；如果多份索引重复路由，同一规则又容易产生多个权威来源。

本设计记录 Easydict 为什么采用当前文档结构。现行规则及目录生命周期以
[`AGENTS.md`](../../AGENTS.md) 和 [`docs/agents/README.md`](../agents/README.md) 为准，
本文不复制完整操作条款。

## 目标

- 为 Agent 提供短小、稳定且唯一的任务入口。
- 让现行规则、设计理由、工作进度、完成结果和外部来源各有明确归属。
- 只加载当前任务所需的最小规则集合，减少无关上下文和维护漂移。
- 让路径、链接和文档边界能够通过机械检查持续验证。

## 非目标

- 不把所有规则集中到 `AGENTS.md`。
- 不建立多层 README 或 guide 作为重复任务路由。
- 不复制或自动同步外部项目的目录、必读清单和 Git 行为。
- 不用设计文档替代当前实现说明、执行计划或完成历史。

## 设计决策

| 位置 | 权威内容 | 主要用途 |
| --- | --- | --- |
| `AGENTS.md` | 唯一入口和任务路由 | 告诉 Agent 当前任务需要读取哪些规则 |
| `docs/agents/request-boundary.md` | 请求与执行边界 | 规定授权、任务状态、Mutation Gate 和子代理边界 |
| `docs/agents/git-workflow.md` | Git 工作流 | 规定状态保护、本地交付、集成和 PR 参数 |
| `docs/agents/build-and-test.md` | 构建与测试 | 规定验证策略、reviewer/tester 和 Xcode 检查 |
| `docs/agents/development.md` | 开发规则 | 规定代码质量、Swift/Xcode 和本地化 |
| `docs/agents/README.md` | 仓库治理 | 规定文档生命周期、受管资产和同步边界 |
| `docs/architecture/` | 当前实现事实 | 描述模块、调用链和运行时边界 |
| `docs/design-docs/` | 长期设计理由 | 记录为什么选择某个重要边界或策略 |
| `docs/exec-plans/` | 执行过程 | 记录获准工作的目标、风险、进度和验证 |
| `docs/histories/` | 完成结果 | 记录已落地变更及其关键背景 |
| `docs/references/` | 精选外部输入 | 记录来源、采用点、本地差异和核对基线 |
| `docs/user-docs/` | 公开文档 | 面向最终用户和外部读者说明产品能力 |

根入口只维护通用约束和任务路由，不复制专题流程。五份专题规则各自维护一个权威职责；
设计文档解释取舍，但链接现行权威而不复制正文。外部参考只提供证据，只有经过本地评估并
写入权威规则后，才会成为 Easydict 的约束。

## 加载与维护

- 每个任务从根 `AGENTS.md` 开始，再按任务读取最小必要的规则。
- 修改文档结构或职责边界时，同时检查入口、相对链接和唯一权威来源。
- 行为或架构发生变化时，在同一任务中更新相关规则、实现说明和公开文档。
- 能够稳定机械验证的路径、链接、格式和结构约束应进入验证流程。
- 过期的入口或重复规则应及时合并、删除或改为指向权威来源的链接。
- 同一专题仍内聚且不超过约 500 行时，不仅为缩短文档继续拆分。

## Easydict 本地适配

Easydict 根据自身的 macOS/Xcode 工程、请求语义、写入前检查和本地交付要求独立定义规则，
不把其他项目的目录、任务索引或 Git 行为视为需要持续同步的模板。

## 重新评估条件

- 根 `AGENTS.md` 再次明显膨胀并承载详细规则。
- 同一约束在两个以上文件中都被视为权威。
- Agent 经常漏读必要规则，现有任务路由无法可靠工作。
- 单个专题超过约 500 行，或已经包含多个可以独立路由的职责。
- 新的文档类别无法归入现有分层，或者现有目录长期没有独立职责。
- 链接和结构无法通过低成本的静态检查保持可信。
