# Agent 文档结构设计

- 状态：adopted
- 初次记录：2026-08-26

## 背景

Agent 需要快速找到当前任务的约束，人类需要理解这些约束为何存在，仓库还需要保留
执行过程、完成结果和外部来源。如果入口、规则、设计理由和参考资料混在同一文件中，
入口会持续膨胀；如果多份索引重复路由，同一规则又容易产生多个权威来源。

本设计记录 Easydict 为什么采用当前文档结构。现行规则及目录生命周期以
[`AGENTS.md`](../../AGENTS.md) 和 [`docs/agents/README.md`](../agents/README.md) 为准，
本文不复制完整操作条款。

## 设计决策

- 根 `AGENTS.md` 保持简明，只维护通用约束和唯一任务路由；专题流程由
  [`docs/agents/`](../agents/) 中各自的权威文件维护。
- `docs/design-docs/` 统一保存产品与技术设计及长期设计决策，但不替代现行 Agent 规则。
- `docs/exec-plans/` 记录获准工作的执行过程，`docs/histories/` 记录已落地结果，
  `docs/references/` 保存反复使用的外部证据，`docs/user-docs/` 面向最终用户和外部读者。
- 历史材料和外部参考可由当前任务明确采纳为本任务约束；只有需要提升为长期仓库规则时，
  才写入现行权威文件。

这种分层避免入口持续膨胀，也避免 README、设计说明、任务记录和外部资料形成多套规则。现行
目录职责与维护要求以 [`docs/agents/README.md`](../agents/README.md) 为准。

## 取舍

- 单一入口和专题规则减少重复，但要求结构变化时同步检查路由和相对链接。
- 设计理由与操作规则分开维护会增加文件数量，但能避免历史背景被误当成当前指令。
- Easydict 根据自身的 macOS/Xcode 工程和交付要求定义规则，不持续复制其他项目的目录或
  Git 行为。

## 重新评估条件

- 根 `AGENTS.md` 再次承载大量专题流程，或同一约束出现多个权威来源。
- Agent 经常漏读必要规则，现有任务路由无法可靠工作。
- 新的文档类别无法归入现有分层，或链接和结构无法通过低成本静态检查保持可信。
