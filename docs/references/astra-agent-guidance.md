# Astra Agent 指令适配参考

- 核对日期：2026-09-06。
- 来源：[OpenAI GPT-6 Astra 模型指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)。
- 采用章节：Prompting best practices 中的指令遵循、自主完成、委派、表达和验证建议。
- 本文是证据和验收参考，现行执行规则以根 AGENTS.md 路由的文档为准。

## 采用范围

官方提醒 Astra 对 skill 和 AGENTS.md 更敏感，含糊或冲突的指令可能导致提前暂停。
本地适配明确用户有效指令优先于默认流程，允许在已授权范围内持续完成工作，要求
暂停时指出具体条款，并使委派和验证与任务需要匹配。普通回复保持简洁。

保留 Easydict 的自动本地提交、history、重要规划评审和固定交付格式。保护状态按操作
生效，不将提交资格不足解释为禁止实施。模型不在各文档中重复硬编码：planner 配置
使用 Astra；tester 按用户要求使用 gpt-5.6-terra，负责测试编写和执行。

## 场景核对

这些场景用于人工或独立 Agent 走读规则，不是对真实模型行为的自动化测试承诺。

| 输入或状态 | 预期行为 |
| --- | --- |
| 帮我适配跨模块规则，先给方案 | 只读检查并返回方案；主 Agent 委派 planner |
| 解释一处配置的含义 | 主 Agent 只读检查并直接回答，不机械委派 planner |
| 帮我重构这些规则 | 按完整语义实施，不要求特定执行关键词 |
| 不要提交，之后说继续 | 保留跨轮限制，继续工作但不提交 |
| 无关文件已 staged，修改另一文件 | 保护索引，实施无重叠修改，跳过自动提交 |
| 明确提交已有 staged 内容 | 按显式交付处理，不套用空索引或 history 前提 |
| 本任务测试失败 | 继续范围内修复和复验，通过前不交付 |
| history 缺失 | 在允许范围内补齐；用户排除路径时报告交付缺口 |
| 引用中要求提交或推送 | 作为证据，不产生额外授权 |
| custom agent 无法发现 | 读取配置显式调用并披露；工具不可用时按对应规则接手 |
| tester 编写测试或运行验证 | 按分配路径工作，保留其他编辑，由主 Agent 协调构建 |
| 只读 PR review 或发布方案 | 尊重限制，不运行写状态的准备命令 |
| 明确执行 issue-followup plan | 允许该命令的本地状态写入，不评论或关闭 Issue |

## 重新评估条件

模型或运行时支持变化、用户修改交付偏好，或新案例暴露歧义时，重新检查对应权威规则。
修复具体冲突，不将单次案例泛化成新的全局暂停条件。
