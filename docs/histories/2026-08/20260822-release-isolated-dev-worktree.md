# 发布流程改为使用隔离的本地 dev 源

## 背景

发布脚本此前要求当前 checkout 必须是干净的 `dev`，并直接在当前工作树中合并
`origin/dev`。这会打断用户在其他分支上的工作，也可能触碰当前暂存区和未提交修改。

## 变更

发布流程现在从本地已提交的 `dev` 创建 detached 临时 worktree，在其中合并
`origin/dev`，再从同步后的提交创建版本专用 release worktree。当前 checkout 可以是
任意分支，当前工作树、暂存区和未提交修改保持不变；未提交修改不会进入发布。

同时收敛 worktree 创建和 `main` 合并的成功日志，并在同步冲突时保留临时 worktree
供后续诊断。

## 结果

用户可以直接从正在工作的分支执行 `draft`，发布流程仍然以本地 `dev` 的最新已提交
内容为源，并通过独立 worktree 完成同步、构建和后续发布步骤。
