## 2026-09-17 | 任务：拆分 Agent 任务模式

**Links:** [`AGENTS.md`](../../../AGENTS.md)

### 用户请求

将根任务入口中的“任务模式”拆分为计划模式、执行模式等子项，提高规则可读性，并明确从方案讨论
切换到实际执行时需要重新检查任务范围和文档治理要求。

### 变更

- 将“任务模式”拆分为“计划模式”“执行模式”“模式切换”和“通用边界”四个子标题。
- 明确计划模式只读，执行模式在首次写入前必须按任务路由读取专题规则。
- 要求所有可能产生仓库差异的任务读取 Plan 与 History 规则，并在模式切换时重新判断
  plan/history 要求。
- 保留原有本地自动提交、外部写入授权和回复语言约束。
- 未新增或修改测试代码。

### 设计意图

根 `AGENTS.md` 继续只承担任务入口和规则路由职责，不复制专题文档中的命名、模板和归档细节。
通过把模式切换和文档治理检查放到执行入口，避免 Agent 将“执行”视为计划讨论的简单续接，进而
跳过 plan 或 history。

- `git diff --check`：通过。
- 相对链接检查：`AGENTS.md` 和 Plan 与 History 专题文档目标存在。
- 手动检查：原有任务模式语义全部保留，层级与任务路由保持一致。
