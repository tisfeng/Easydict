## 2026-09-17 | 任务：拆分 Agent 任务模式

**Links:** [`AGENTS.md`](../../../AGENTS.md)

### 执行上下文

- **Agent Name:** `Codex`
- **Model:** `gpt-5.6-sol`

### 用户请求

将根任务入口中的“任务模式”拆分为计划模式、执行模式等子项，提高规则可读性，并明确从方案讨论
切换到实际执行时需要重新检查任务范围和文档治理要求。

### 变更

- 将“任务模式”整理为“计划模式”“执行模式”和“通用规则”三个子标题。
- 合并“模式切换”和“通用边界”，统一承载跨模式的授权、外部写入和语言规则。
- 将执行模式压缩为“执行前”“实现与验证”“Review”和“交付”四步编号流程，减少标题与重复表述。
- 将 Review 保留在执行模式内，并明确它在实现完成且必要验证通过后进行。
- 将计划模式压缩为单条只读规则，不再重复执行授权后的 plan/history 处理。
- 由“执行前”唯一负责专题规则和 plan/history 判断，“通用规则”只保留授权与模式切换边界。
- 要求所有可能产生仓库差异的任务读取 Plan 与 History 规则，并在模式切换时重新判断
  plan/history 要求。
- 明确适用的 Review 通过后才进入 history、plan 归档和本地提交等交付步骤。
- 保留原有本地自动提交、外部写入授权和回复语言约束。
- 未新增或修改测试代码。

### 设计意图

根 `AGENTS.md` 继续只承担任务入口和规则路由职责，不复制专题文档中的命名、模板和归档细节。
通过把文档治理检查放到执行入口，避免 Agent 将“执行”视为计划讨论的简单续接，进而跳过 plan
或 history。执行模式使用编号流程保留“执行前 → 实现与验证 → Review → 交付”的先后关系；跨模式
约束集中到“通用规则”，使根入口更短且仍可快速扫描。计划模式只描述只读边界，执行授权后的
文档治理统一由“执行前”负责，避免同一规则分散在三个位置。
