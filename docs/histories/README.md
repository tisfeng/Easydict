# 变更历史

`docs/histories/` 记录所有最终产生仓库文件差异的 `implementation` 任务。文件类型、数量、
变更规模以及是否创建 execution plan 都不影响该要求；最终没有仓库文件差异的任务不创建
空记录。

## 规则

- 每个产生仓库文件差异的 `implementation` 使用一条历史记录，无论是否关联 Issue 或 PR。
- 同一任务分多轮处理时，继续使用同一条 history。
- 仅修改 history 的任务由该记录描述自身，不递归创建第二条 history。
- 保持用户请求简洁，并移除机密信息、本地路径和原始日志。
- 记录设计意图、受影响文件、验证结果和已知后续事项。
- 存在执行计划时，链接对应的执行计划。
- 交付时将 history 与同任务其他变更一起验证和精确暂存；允许提交时进入同一个提交。
- 有效的禁止提交要求或交付条件不满足时，保留 history 与任务变更；局部操作受阻不
  阻止允许范围内补齐记录。用户排除 history 路径时遵循该限制并报告交付缺口。
- 历史文件统一命名为 `YYYY-MM-DD-<slug>.md`，其中 `<slug>` 使用小写 kebab-case；文件
  继续归档到 `YYYY-MM/` 目录下。
- 新建或修改的标题与正文遵循用户当前请求的语言；技术标识和引用路径保留原文，
  不为语言统一批量改写历史记录。

新建记录时使用 `template.md`，并将其归档到 `YYYY-MM/` 下。
