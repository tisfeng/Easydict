## 背景

用户在 issue #1389 提出添加 Bing 词典作为查词备选。现状是 `BingService` 的词典模式依赖
`api/v7/dictionarywords/search` JSON API，匿名请求 403（InsufficientAuthorization），实际
多走静默降级路径，只显示中文释义。实测 `https://cn.bing.com/dict/search?q={word}` 页面
匿名可访问（HTTP 200），网络释义的双语编号词义为服务端直出（`bil`/`val` span + 扁平
`tr.def_row`），完整调研见 issue 评论。

## 目标与范围

- 目标结果：新增独立 `BingDict` 词典服务，展示必应词典双语（中英）词义。
- 允许修改路径：`Easydict/Swift/Service/Dictionary/BingDict/`（新增）、
  `EZEnumTypes.h/.m`、`QueryServiceFactory.swift`、`Localizable.xcstrings`、
  `project.pbxproj`、`EasydictTests/Service/BingDictHTMLParserTests.swift`（新增）。
- 同任务 history：`docs/histories/2026-11/2026-11-04-bing-dict.md`
- 用户限制：不使用 Youdao；不改动既有 `BingService` 翻译行为。
- 非目标：懒加载词典 Tab（高级英汉/英汉/英英 Collins 数据）、发音音频、例句缓存。
- 验收标准：查询单个英文单词时，`BingDict` 服务渲染双语词义（CN + EN 完整句），
  匿名可请求，无 Cookie 配置。

## 工作计划

1. 注册 `BingDict` ServiceType（ObjC string enum + factory + 本地化）。
2. 实现匿名页面请求（`BingDictRequest`）与服务（`BingDictService`，`.dictionary` 查询类型，
   `DictionaryHTMLRenderer` 渲染）。
3. 实现纯 Foundation 解析器（`BingDictHTMLParser`）并配离线 fixture 单元测试。
4. 同步 `project.pbxproj`（新文件与 build phase 引用）。
5. 在具备完整 Xcode 的环境构建、跑测试并做界面验证。

## 风险与决策

- 页面结构变化风险：解析锚点（`tr.def_row`、`bil`/`val` span、meta description）为服务端
  直出；若 Bing 改版需更新正则。`val` span 内嵌spacer `<span> </span>`，采用平衡扫描而非
  非贪婪匹配（实测非贪婪会截断英文释义）。
- 语言范围：仅英文单词（`shouldQueryDictionary` + `from == .english` 门槛），非英文或非单词
  返回 noResult，保持服务可预期。
- 无 Xcode 环境风险：本机仅 CLT，可独立编译验证 parser，但 app target 构建与
  UI 验证必须留在有 Xcode 的环境完成（见验证）。
