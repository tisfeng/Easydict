## 背景

自动本地提交已经执行成功时，最终回复可能只显示短哈希和标题，导致用户无法确认提交
动作与完整提交内容。`worktree-rebase-merge` 另外维护了更严格的展示要求，使同一提交在
两个工作流中的报告详细程度不一致。

## 任务契约

- 用户目标：统一提交后的用户可见结果，并增加总变动、代码变动和文档变动信息。
- 允许动作：修改仓库 Agent 指南、`git-commit` 与 `worktree-rebase-merge` skill，
  增加统计脚本、行为测试、计划和历史。
- 允许修改路径：`.agents/skills/git-commit/`、
  `.agents/skills/worktree-rebase-merge/SKILL.md`、`docs/agents/repository-guide.md`、
  本执行计划和完成历史。
- 预期交付物：唯一提交后报告契约、确定性文本行统计和复用提交说明。
- 验收标准：统计可复算，行为测试和静态检查通过。

## 目标

- 由 `git-commit` 统一定义成功提交后的用户可见结果。
- 明确区分本次创建提交与复用源分支已有提交。
- 展示完整提交哈希、完整实际提交信息、工作树状态和 push 状态。
- 展示可复算的总变动、代码变动和文档变动文本行数。
- 静默忽略二进制文件，不在最终结果中显示二进制统计。

## 非目标

- 不修改产品代码、构建配置或运行时资源。
- 不改变 staging、commit、rebase、merge 和 push 的授权边界。
- 不为单一案例复制第二套提交展示模板。

## 工作计划

1. 为 `git-commit` 增加确定性的提交变动统计脚本和行为测试。
2. 在 `git-commit` 中定义唯一的提交后报告契约。
3. 让 `worktree-rebase-merge` 复用该契约，并补充提交来源与集成状态。
4. 在仓库自动提交规则中要求完整、用户可见的提交结果。
5. 完成 skill 校验、脚本测试、静态检查和文档归档。
