## 背景

合并后的 OCR 选择支持独立识图和翻译；相同模型仍产生两次请求。交叉输出曾出现通道串流，缓冲双字段会推迟首次可见内容。现采用原文完成后再译文的顺序 JSON 流，并在原文完成时分发其他翻译服务。

## 目标与范围

- 目标结果：同一配置的识图和翻译合并为一次图片请求，顺序流式显示两个输出。
- 允许修改路径：OCR 功能、请求编排、服务协议及 Codex/DeepSeek 请求格式、查询窗口接线、对应测试、工程引用和本任务文档。
- 同任务 history：`docs/histories/2026-11/2026-11-13-sequential-ocr-translation.md`
- 用户限制：保护本机密钥与配置；测速结果如实记录；提交新的 PR。
- 非目标：启用全局 Fast、改变思考强度、改造 OCR 服务扫描、搬入本机测速工具。
- 验收标准：闭合公式即时复用现有渲染；完整原文仅分发一次；取消、输入变更和双窗口无旧结果污染；真实 Codex 与 DeepSeek 验证，PR 包含测量口径及已知限制。

## 工作计划

1. 以最新 dev 30b53c9b 为基线，移植最小生产改动。
2. 实现两字段 JSON 增量解码、顺序显示及完整原文分发。
3. 验证协议分块、取消、重入和配置变动，重复调用真实服务。
4. 审查、记录验证和测速结果，本地提交后创建新 PR。

## 风险与决策

- 使用结构化输出减少先前实测的 JSON 格式失败；严格校验完成结果，失败时保留已显示内容并报告错误。
- 服务配置仅在内存比较，原文和响应正文不进入测试产物或错误信息。
- 测速来自独立测试宿主的历史三次成功样本，单列失败和波动；不能作为最终实现的稳定性结论。
