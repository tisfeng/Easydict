基础查询窗口架构概览

本目录定义查询 NSWindow 与其主控制器的公共骨架。窗口负责 AppKit 外壳、标题栏、pin/level 和位置尺寸委托；控制器负责把输入文本与有效语言方向变成并行服务请求，再把服务结果、提示和标题栏状态同步到同一窗口。

核心责任与边界

组件核心责任外部边界
EZBaseQueryWindow创建透明标题栏的主/固定/迷你查询外壳，持有 controller 和 EZTitlebar；处理 key/resign、resize、move 与 pin level。窗口选择与复用交给 EZWindowManager，尺寸策略交给 EZLayoutManager。
EZBaseQueryViewController持有 EZQueryModel、输入/语言单元格、服务结果表、探测器和音频；协调输入、探测、查询、历史记录与结果刷新。服务实现由 QueryService 提供，选中的服务集合来自 LocalStorage。
EZQueryModel保存 inputText、queryText、用户/探测/有效源语言、目标语言、action type 和服务取消状态。是查询窗口内的当前真相，不是 Wordbook 的持久化模型。
EZTitlebar显示 pin、quick action、链接和 Wordbook star；每次查询上下文变化后读取 model 快照。星标持久化由 Swift WordbookManager/Repository 完成。

文本与有效语言转换

  1. 外部入口把原始文本设为 inputText；setter 复制字符串并写入 queryModel，避免调用方后续修改影响当前查询。
  2. 普通取词路径清理不可见字符、边缘空白和 Books 摘录信息；Wordbook/History 重放路径开启 preserveQueryText，不重写保存原文。
  3. 没有保存语言时，needDetectLanguage 为真则异步探测；完成回调先比较当前 queryText，旧文本的探测结果直接丢弃。
  4. 有保存的 from/to 时，先取消延迟探测，把 userSourceLanguage/userTargetLanguage 写入 model，并据源语言是否 Auto 决定是否仍需探测。
  5. 手动切换 source/target 或修正探测语言时，retry 路径在关闭旧结果前同步刷新标题栏；Auto 源语言会立即让星标进入等待探测状态。
  6. 文本写入和异步探测完成仍通过统一模型更新刷新输入单元格、语言单元格和 Wordbook star；因此星标只使用当前 inputText 与有效方向。
可见原文与服务文本：服务可以使用规范化后的 queryText，但标题栏保存必须使用 inputText。有效语言方向来自 queryFromLanguage/queryTargetLanguage；未解析自动源语言时星标保持禁用。

正常查询与结果流

  1. 开始新查询前停止旧服务、关闭旧结果；若窗口未 pin，WindowManager 先重置表格和高度再展示。
  2. 控制器在需要时探测语言，然后把同一个 queryModel 交给所有启用且支持当前查询类型的服务。
  3. 每个服务独立进入 loading，并通过 stream completion 更新自己的 EZQueryResult 和结果单元；错误被转换为 QueryError，不阻塞其他服务。
  4. 首个可用服务可以驱动自动复制；所有服务调度后记录查询次数，并把 queryText 与最终 from/to 写入 Query History。
  5. 结果/iframe 高度变化由控制器汇总并限制在 LayoutManager 的最小/最大窗口尺寸内，窗口 delegate 再持久化用户移动与 resize。

标题栏刷新触发点

触发模型变化星标期望
输入 setter / 清空inputText 与 queryText 变化新 key lookup；空输入立即变 empty。
Wordbook/History 重放保存的 from/to 被应用以保存方向 lookup，避免错误 auto 语言。
自动语言探测完成detectedLanguage 与有效方向确定从 resolving 进入 checking，再 absent/present。
用户切换语言或重试语言needDetectLanguage、detected/user language 改变旧 generation 失效，按新方向重新判断。
标题栏配置/应用语言通知按钮栈或本地化变化重建 host 后从当前 model 恢复。

失败与恢复流

  • 空输入：不开始查询；普通快捷键取词失败时可显示提示，preserved replay 的空文本直接拒绝并记录警告。
  • 旧语言回调：文本比较失败即忽略，不更新语言单元或标题栏；用户可重新输入或显式选择语言。
  • 单个服务失败：结果单元显示对应错误，其他服务继续；用户可通过 retry 以 Auto 语言重新执行。
  • 服务配置更新：接收 serviceHasUpdated 后重建对应服务或完整列表；需要时用当前 model 自动再查询。
  • 窗口尺寸/iframe 振荡：resize guard、frame tolerance 与 needUpdateIframeHeight 合并重复更新，最后限制在布局边界。
  • Wordbook 不可用：只影响星标状态，不中断翻译服务和 Query History 写入；Repository 恢复后通知星标重新 lookup。

调试与验证入口

  • 输入/语言错误从 setInputText、stored-language 应用、detectQueryText、统一 model/UI 更新链路排查；日志中的 query from → to 应与选择器和星标一致。
  • 服务结果缺失时检查 latestServices、enabledQuery/autoQuery/query type gate、startQueryStream completion 和结果单元映射。
  • 快速切换两段文本，确认第一段延迟探测不会更新第二段语言；从 Wordbook 与 History 分别重放，确认输入原文及 source/target 保留。
  • 窗口高度异常时检查 table row height、iframe loaded/needUpdate 标记和 LayoutManager min/max；多显示器移动后检查当前 window.screen。
  • 手工模拟服务错误、配置更新和 retry，确认错误局限于服务结果，标题栏与窗口仍可交互。
