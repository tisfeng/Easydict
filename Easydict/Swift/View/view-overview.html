共享视图层架构概览

Swift/View 是 SwiftUI 界面与既有 AppKit 应用生命周期之间的适配层。它提供菜单入口、设置页、可复用宿主窗口和轻量 NSView bridge；具体翻译、单词本持久化与查询服务状态应留在各自的 Feature、Service 或 Objective-C 控制器中。

目录职责

区域代表组件拥有的责任
菜单栏入口MenuItemView组合翻译、OCR、单词本、设置、更新与退出动作；菜单只路由意图，不嵌入业务界面。
AppKit 宿主Window/HostWindowManager在主线程创建 NSWindow、NSHostingView 和 NSWindowController，以稳定 id 管理控制器所有权、窗口复用和激活。
设置界面SettingView 与 Tabs组织用户偏好页，借助 WindowAccessor 根据选中标签控制设置窗口大小。
桥接小组件WindowAccessor、TapHandler把 SwiftUI 无法直接表达的 NSWindow 获取和 AppKit 点击事件限制在很小的适配边界内。
共享展示AdvancedTabItemView 等统一常用布局和视觉语义，不持有跨功能业务状态。

单词本窗口入口与生命周期

  1. MenuItemView 的“Wordbook…”动作调用 HostWindowManager.shared.showWordbookWindow()。
  2. HostWindowManager 以 wordbook.window 为稳定 id。首次打开时创建 900×640、可调整大小的 AppKit 窗口，把 WordbookView 包进 NSHostingView，并由字典中的 NSWindowController 强持有。
  3. 该窗口启用 reuseExisting 且 isReleasedWhenClosed = false。用户点击红色关闭只隐藏/关闭可见窗口，控制器与 SwiftUI 根视图仍被 manager 持有；再次打开会激活同一窗口，而不是重建 ViewModel。
  4. 激活复用窗口时先更新本地化标题，再激活应用、显示控制器并 makeKeyAndOrderFront；因此搜索、分区、排序及尚存的窗口会话状态可跨关闭/重开保留。
所有权边界：HostWindowManager 拥有“窗口/控制器存在多久”，WordbookView 拥有“窗口内部状态如何展示”，WordbookRepository 拥有“业务数据是否安全”。任一层都不应越过另外两层直接释放或伪造状态。

本地化环境

  • 打开窗口时，HostWindowManager 使用 I18nHelper.shared.localizeCode 选择精确的 .lproj bundle，并以 wordbook.window.title 生成标题；不假设 String(localized:locale:) 会切换资源 bundle。
  • WordbookView 持有 LanguageState，把对应 Locale 注入 SwiftUI environment；列表元数据、日期、计数、完整提示句和导出文件名都从同一 locale 计算。
  • WordbookView 观察自身 LanguageState 已更新后的新值，用同一语言代码更新 ViewModel 查询 locale，并通过 HostWindowManager 更新现有 NSWindow 标题，避免同步通知早于另一个 AppStorage 实例刷新的竞态。
  • 动态语言名、日期与插值句由 ViewModel/子视图在 locale 边界一次性格式化；共享视图层不拼接本地化片段，也不构造动态 catalog key。

进出边界与正常流

方向输入/输出约束
外部 → 菜单用户点击、键盘快捷键、Sparkle 更新状态菜单将动作交给 ShortcutAction、HostWindowManager、Settings 或 updater，不保存翻译数据。
菜单 → 单词本窗口稳定窗口 id、本地化标题、WordbookView 构造器仅激活或创建独立窗口；不把 Wordbook/History 放回 Settings TabView。
SwiftUI → AppKitNSHostingView、NSWindowController、WindowAccessor所有窗口变更在 MainActor；控制器字典是显式生命周期根。
功能层 → 视图ObservableObject、通知、Defaults publisher视图订阅并呈现；写入仍走功能层定义的门和事务。
视图 → 系统窗口激活、Finder、保存面板、URL只在用户动作或明确完成回调中产生系统副作用。

失败与恢复

  • 复用表中没有控制器：按首次打开路径创建；已有控制器但窗口不可见时直接 show + order front。
  • 语言切换：不重建窗口，通过 environment 与标题更新恢复一致；业务数据不受语言变化影响。
  • Wordbook 加载/写入失败：共享视图层不吞掉错误，WordbookView 按 Repository phase 显示重试、Finder 或保护式重置。
  • 菜单动作失败：更新检查、日志导出或 URL 打开由各自服务记录日志；不能牵连 HostWindowManager 的控制器字典。
  • 生命周期异常：若红色关闭后状态丢失，优先检查 reuseExisting、isReleasedWhenClosed 和 controller 是否仍在字典中，而不是给 ViewModel 添加额外持久化。

调试与验证入口

  • 从菜单栏连续两次打开 Wordbook，确认同一窗口被前置且没有重复 NSWindowController；红色关闭后重开，确认搜索和当前 section 保留。
  • 切换六种应用语言，检查菜单项、窗口标题、日期/计数和错误提示同步更新；特别检查窗口已打开时的 .onChange(of: languageState.language) 路径及精确 .lproj 查找。
  • 窗口未出现时从 MenuItemView.wordbookItem → showWordbookWindow → activateWindow/showWindow 排查；观察 window id 是否一致。
  • 设置窗口尺寸异常时检查 WindowAccessor 是否取得当前 NSWindow，以及 selection 变化是否触发 resize；点击与拖拽冲突则检查 TapHandlerView 的 AppKit 事件边界。
  • 手工验证 Finder/保存面板等系统出口时，同时确认取消操作不会产生 Repository 写入或清除窗口状态。
